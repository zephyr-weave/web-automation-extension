# 异常分支手册：主流程之外的 90% 工程量

> 对应六步法第 2 步。原则：主循环一句话能说清；把精力花在"坏情况怎么办"的清单上。
> 自动化软件 90% 的工程量在异常分支。**不允许静默失败。**

## 1. 异常分支表（模板）

| 坏情况 | 检测方式 | 动作 |
|---|---|---|
| 目标元素找不到 | 轮询超时 | 提示用户手动指定，不空转 |
| 点击后无任何反应 | 结果等待超时 | 分级：先提示"已等待 N 秒" → 再自动暂停 |
| 平台风控触发（验证码） | 特征文本/DOM 检测 | **不代答**，暂停交还用户，说明原因 |
| 网络断开 | navigator.onLine + offline 事件 | 立即暂停，可恢复后继续 |
| 接口报错 | 错误提示 DOM 特征（文本匹配"网络/超时/失败/错误"） | 立即暂停，说明原因 |
| 翻页/状态不前进 | 前后状态签名对比 | 重试一次 → 仍失败则停止并提示 |
| 任务自然完成 | 末页判定信号 | 明确播报"完成 N 步"，回待机态，**不误报为异常** |

## 2. 检测策略分层

- **精确检测优先**：有事件信号就用事件（如下载开始/完成事件），不用猜
- **兜底必须存在**：精确检测失效时（浏览器限制、事件不触发），提供粗糙但永远可用的备选（如固定等待 N 秒），让用户有路可走
- **分级提示**：同一问题先提示（20 秒无反应→提示确认），后自动暂停（35 秒无反应→暂停），给用户反应时间

## 3. 状态机：三态分离

```
待机 ──开始──▶ 运行 ──暂停──▶ 已暂停 ──继续──▶ 运行
                │                │
                └──停止/完成─────┴──▶ 待机
```

- **暂停 ≠ 停止**：暂停保留全部现场（进度、计时），点"继续"从断点恢复；停止 = 彻底回待机
- 每个等待循环都要检查暂停/停止标志，**暂停必须能立刻中断长等待**，不能等当前 sleep 自然结束才响应（长 sleep 会让暂停按钮"假死"）
- 到末页自动停止属于任务完成，播报"本次共完成 N 步"，状态回待机——不能显示成"已暂停"误导用户

## 4. 频率与风控

- 摸清红线的确切数字（如"30 秒最多 3 次"），默认节奏设置在阈值内并留余量（如 12 秒/次）
- **绝不代答验证码**：尊重站点风控，检测到即暂停，用户手动完成后点"开始"继续
- 开始计时要从每次实际动作刷新，不是从任务开始
