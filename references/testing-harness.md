# 测试 harness 使用指南

> 对应六步法第 4 步。目标：任何自动化主循环都能在 10 分钟内搭出端到端测试。

## 快速开始

```bash
cp scripts/new-test-template.js test_<scenario>.js
# 改三处：1) html 常量里的假站点结构 2) "模拟站点行为"区 3) 底部的断言
node test_<scenario>.js   # 退出码 0 = PASS
```

## 仿真站点四要素

任何网页自动化的被测系统，都用这四样复刻：

1. **目标按钮响应**：给按钮挂监听器，点击后按真实时序产生后续变化（计数器 +1、N 毫秒后弹窗）
2. **弹窗/浮层**：按实测延迟出现，"确认"按钮触发结果流，完成后移除
3. **状态变化**：如分页器页码前进、末页时按钮加 `is-disabled` + `disabled`
4. **异步结果事件流**：如下载开始/完成——模板用 `fireDL('created'/'complete')` 直接调 chrome onMessage 监听器模拟 background 转发

## 模板已处理的脏活

- `getBoundingClientRect` 桩（jsdom 无布局，非零矩形模拟可见元素）
- chrome API mock（runtime.sendMessage/onMessage、tabs）
- `runScripts: 'outside-only'` + `eval(contentCode)`（把 content script 放进页面上下文）
- 全局对象注入（window/document/localStorage/CSS/MutationObserver/navigator）
- 预置 localStorage 设置（可缩短间隔加快测试）

## 计时预算规则

1. **先实测单轮耗时**：手动跑一轮数秒数，或从日志时间戳算
2. 测试超时 = 单轮耗时 × 轮数 × 2（留抖动余量）；案例：单页 5s × 3 页 → 断言放在 17s、退出 19s
3. 长场景拆阶段，每阶段打印中间结果，失败时能定位到哪一轮

## 断言原则

- **断言行为，不断言实现**：断言"导出按钮被点了 3 次""面板显示已导出 3 页"，不断言某函数被调用
- 日志断言用特征字符串（如 `/最后一页/`），注意区分**日志文本**与**面板文本**（案例教训：日志写"本次共导出 3 页"，面板才写"已导出 3 页"，断言错了对象会误报失败）
- 失败时打印诊断值（计数、日志尾部），不要只报 FAIL

## 测试环境硬限制与绕法

| 限制 | 绕法（不改产品语义） |
|---|---|
| 伪造不了 `isTrusted=true` | 用"合成点击不被吞掉"反证守卫有效 |
| `media.play/pause` 未实现 | 打桩计数，断言音频元素生命周期 |
| 无真实浏览器节流 | 标注进"真机验证清单"，不硬测 |

## 场景矩阵（按此扩展）

正常流 / 暂停继续 / 每个异常分支（验证码、离线、接口错误、超时、关闭）/ 每个新功能（重置、守卫、保活）——一个文件一个场景，文件名即文档。
