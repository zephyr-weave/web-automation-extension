# 摸现场清单：编码前必须采集的目标站点信息

> 对应六步法第 1 步。原则：不急着写代码，先把"要对谁做什么"摸成一张清单。
> 产出物：**操作流程图 + 约束红线清单 + 异常出口表**，三样齐了才允许进入设计。

## 1. 交互流程与时序

- [ ] 完整操作链：从触发到结果，每一步是什么（点击什么 → 出现什么 → 再点什么）
- [ ] 每步时序：点击后多久出弹窗、多久出结果、多久可进行下一步（用秒计量，这决定所有等待超时值）
- [ ] 哪些步骤是同步生效、哪些是异步延迟（异步的必须做完成检测，不能靠猜）
- [ ] 循环边界：任务自然完成的判定信号是什么（如"下一页按钮禁用""页码到达最大值"）

## 2. DOM 结构采集

- [ ] 关键元素的定位特征：标签名、class、id、title、aria-label、data-* 属性
- [ ] **稳定性分级**：哪些属性在页面重渲染后不变（稳定），哪些会漂移（易变）
  - 稳定候选：`title` / `aria-label` / `data-testid` / `data-id` / `name` / `placeholder`
  - 易变：纯样式 class、`:nth-of-type` 序号路径（SPA 重渲染后会错位）
- [ ] 弹窗/浮层的容器特征（如 `.el-dialog` / `[role="dialog"]` / `[class*="modal"]`）
- [ ] 分页器结构与禁用态特征（class 含 `is-disabled` / `disabled` 属性 / `aria-disabled`）
- [ ] 表格 loading 态特征（如 `.el-loading-mask`），用于判断"渲染完成"

## 3. 约束与红线

- [ ] 频率限制：多长时间内最多允许多少次操作，超限的后果（弹验证码 / 封禁 / 报错）
- [ ] 验证码/风控：触发条件、形态（算术题？滑块？）、**决定插件策略：检测到即暂停交还用户，不代答**
- [ ] 登录态：是否依赖会话、插件是否触碰登录（答案应当是不触碰）
- [ ] 浏览器权限：首次操作是否会弹权限（如"允许下载多个文件"），需要在文档里提示用户点允许

## 4. 异常出口

- [ ] 断网时页面表现（navigator.onLine / offline 事件 / 错误提示）
- [ ] 接口失败时页面表现（红色 toast？文字含"网络/超时/失败/错误"？）
- [ ] 目标元素找不到时的表现（按钮根本不出现 vs 出现但禁用）
- [ ] 结果迟迟不来时的表现（永久转圈？最终超时报错？）

## 5. 侦察手段

- 浏览器 DevTools：Elements 面板看结构，Console 里试 `document.querySelector` 验证选择器唯一性
- 手动完整走一遍流程，同时计时——把时序数字记录下来
- 连点几次触发风控，亲眼看验证码长什么样、限制窗口有多长
- 断网（DevTools → Network → Offline）走一遍，看错误提示的 DOM 特征

## 反模式

- ❌ 只看一眼截图就开始写选择器（重渲染后必漂移）
- ❌ 用 `:nth-of-type` 路径一写到底（SPA 场景等于埋雷）
- ❌ 没测频率限制就按"尽可能快"设计（必然撞风控）
- ❌ 只摸了正常路径，没摸异常出口（90% 的工程量在异常分支）
